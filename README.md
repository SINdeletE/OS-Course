# XP-PEN Deco Fun L → относительная мышь

Загружаемый USB-модуль `xppen_mouse` для устройства `28bd:0932`.
Целевая ОС — Ubuntu 24.04.3 ARM64, ядро `7.0.0-43-generic`.
**Весь каталог проекта размещается внутри Ubuntu. Все команды ниже выполняются
в терминале Ubuntu из этого каталога.** Для работы проекта macOS и средства
удалённого запуска не нужны.

В Parallels предварительно подключите физический планшет к Ubuntu через меню
«Устройства → USB». `lsusb -d 28bd:0932` должен показывать сам планшет.
Наличие виртуальной мыши Parallels или движение курсора этого не подтверждает.

## Подготовка и сборка

```bash
sudo apt update
sudo apt install build-essential python3 kmod usbutils evtest linux-headers-$(uname -r)
make
modinfo -F vermagic ./xppen_mouse.ko
uname -r
```

Начало `vermagic` должно совпадать с `uname -r`. После обновления ядра нужны новые
заголовки и повторная сборка. `KDIR` — каталог сборки ядра; по умолчанию он равен
`/lib/modules/$(uname -r)/build`. Обычно переопределять его не требуется:

```bash
make KDIR=/lib/modules/7.0.0-43-generic/build
```

Kbuild выбирает GNU11 и флаги ядра; принудительный `-std=c99` не используется.

## Загрузка, привязка и выгрузка

```bash
sudo make load
sudo evtest
# Выберите «XP-PEN Deco Fun L relative mouse»; выход из evtest — Ctrl+C.
sudo make unload
```

`load` собирает и загружает модуль, затем перепривязывает USB-интерфейсы 0 и 1
только у `28bd:0932`. Интерфейс 0 занят без опроса, чтобы исходные мышь и клавиатура
планшета не дублировали ввод. Интерфейс 1 опрашивается нашим драйвером через URB.
Интерфейс 2 и остальные USB-устройства остаются у своих драйверов.

После отключения и повторного подключения планшета к Ubuntu выполните:

```bash
sudo make bind
```

Эта же команда переинициализирует приём после ошибки восстановления endpoint.
Если планшет отсутствует при `load`, модуль остаётся загруженным; подключите
планшет и выполните `bind`. Автоматическое переключение через udev не устанавливается.

Предыдущие привязки сохраняются в `/run/xppen-mouse/bindings.json`. `unload`
выгружает модуль и восстанавливает их. При частичной ошибке привязки выполняется
откат; если восстановление не удалось, исправьте причину и повторите
`sudo make unload`. Используйте именно эту команду вместо отдельного `rmmod`,
чтобы штатные драйверы снова подключились. Глобально выгружать `usbhid` не нужно.

При переподключении имя USB-интерфейса может измениться. Скрипт заново проверяет
VID/PID и номер интерфейса, а не полагается на адреса из примера диагностики.

## Поведение и чувствительность

- Наведение и движение с касанием перемещают курсор относительно его положения.
- Касание удерживает ЛКМ и позволяет перетаскивать объекты.
- Первая боковая кнопка (HID Barrel Switch, бит `0x02`) удерживает ПКМ.
- Вторая кнопка, давление и наклон игнорируются.
- Выход пера из зоны считывания освобождает кнопки; возвращение не вызывает скачок.

Делитель перемещения по умолчанию — `8`. Меньший делитель увеличивает скорость.
Параметр задаётся только при загрузке, допустимый диапазон — `1…1024`:

```bash
sudo make unload
sudo make load DIVISOR=4
```

При `load` уже загруженного модуля его параметр сохраняется. Остатки деления
накапливаются отдельно по осям, поэтому медленное движение не теряется.

## Устройство драйвера

Весь код модуля находится в `src/main.c`. Это `struct usb_driver`, а не обработчик
событий штатного драйвера. На интерфейсе пера выбирается interrupt IN endpoint
(у проверенного планшета `0x82`, 64 байта, 4 мс), устанавливается Report Protocol,
выделяются URB и DMA-буфер. Completion callback проверяет статус, разбирает
10-байтовый отчёт №7 и повторно отправляет URB. События выходят через Linux Input
Subsystem как `REL_X`, `REL_Y`, `BTN_LEFT`, `BTN_RIGHT`.

Раскладка отчёта подтверждена HID-дескриптором этого устройства: байт 1 содержит
касание (`0x01`), кнопку (`0x02`) и нахождение в зоне (`0x20`); байты 2–3 и 4–5 —
X и Y little-endian в диапазоне `0…32767`. Неподходящие пакеты игнорируются.

Остановка сначала запрещает повторную отправку под spinlock, затем дожидается
URB и recovery work. Восстановление `-EPIPE` выполняется в workqueue. После
ошибки восстановления приём прекращается, кнопки освобождаются. Suspend и USB
reset останавливают приём; resume заново устанавливает протокол и запускает URB.

## Проверка на целевом устройстве

Сборка модуля всегда включает `W=1`.

После `sudo make load`:

```bash
lsusb -t
cat /proc/bus/input/devices
sudo evtest
sudo dmesg --follow
```

У планшета интерфейсы 0 и 1 должны использовать `xppen_mouse`, интерфейс 2 —
штатный драйвер. Новое устройство должно сообщать относительные координаты,
не `ABS_X/ABS_Y`. Проверьте:

1. Наведение, движение в обе стороны и очень медленное движение.
2. Касание, отпускание, перетаскивание, первую и вторую боковые кнопки.
3. Подъём пера и возвращение в другой точке без скачка курсора.
4. Отключение USB при нажатых кнопках, переподключение и `sudo make bind`.
5. Suspend/resume, повторные load/unload, восстановление штатной работы.
6. Отсутствие дублирования ввода, ошибок ядра и изменений работы мыши/клавиатуры Parallels.

USB-транспорт проверяется на планшете. Факт успешной сборки не означает
прохождение этих пунктов.

Если загрузка отклонена с `Key was rejected by service`, проверьте политику подписи
модулей целевой ОС и подпишите модуль доверенным ключом. Ошибки загрузки и USB
обмена смотрите в `sudo dmesg`. Для очистки артефактов сборки используйте `make clean`.
Очистка удаляет объектные файлы, модуль, скрытые `.cmd` и зависимости Kbuild
в корне проекта и `src/`. Она работает
даже без установленных заголовков ядра и не требует `KDIR`.
